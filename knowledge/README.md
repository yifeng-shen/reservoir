# knowledge/ · 公开知识库

> 只放**可公开、可跨项目复用**的行业知识与运营方法。
> 自有打法、项目数据、供应商条件、单店财务，一律放私密层。

## 边界

| 内容 | 去哪 |
| --- | --- |
| OTA 平台规则、行业定义、公开报告 | 本目录 `ota/` |
| 通用运营方法、可公开的 SOP | 本目录 `ota/` |
| 你的定价策略、渠道成本、供应商条件 | 私密层 `knowledge/` |
| 具体项目/门店的数据、人员、决策 | 私密层 `projects/<项目>/` |
| 脱敏后的项目复盘 | `archive/projects.md` |

判定标准：**是否愿意让竞争对手和搜索引擎看到。** 不愿意，就不进公开层。

## 目录

| 文件 | 内容 |
| --- | --- |
| [`ota/platforms.md`](ota/platforms.md) | 携程 / 美团 / 飞猪 / 抖音 / 小红书等平台规则 |
| [`ota/traffic.md`](ota/traffic.md) | 搜索排序、流量入口、转化漏斗 |
| [`ota/pricing.md`](ota/pricing.md) | 定价模型、价格带、促销、渠道成本（公开部分） |
| [`ota/reviews.md`](ota/reviews.md) | 评分规则、评价获取、差评处理 |
| [`ota/operations.md`](ota/operations.md) | 日常 / 周 / 月运营 SOP 与数据看板 |

## 写作要求

- 每个结论必须带**来源**与**获取日期**，不能只写「经验上」。
- 区分事实、推断、观点；推断标注「推断」。
- 不写具体项目、门店、合作方的名字与数字。
- 平台规则会变，过时内容标注失效日期，不要直接删除。
- 新知识先写进对应文件，不要建新顶层目录。

## AI 权限

`AI-EDIT`：可以补充和修订，但必须保留原意、更新 `updated`、在文末「变更记录」登记。
不确定的内容先写进 `memory/inbox.md`，不要直接当事实写入。
